# 試用準備：設定と結果の保存・復元

2026-09-16。試用→バグ修正→EXE・インストーラーの順で進めるため、今回は永続化を独立した開発単位として完了させます。まだ一般的な試用版完成の判定ではありません。

## 今回実装した範囲

- OCR、言語、OCR実行方式、表・画像設定、ページ上限、保存先を保存し、次回起動で復元。
- 変換結果は1PDF処理ごとにローカルDBへ保存。入力の個別エラーも保存。
- 最新20件の履歴選択、再変換せず結果を復元、履歴を個別削除。
- 途中終了の履歴は「完了未確認」。保存済み部分だけ復元し、全体成功とは表示しない。
- DB破損や書き込み失敗は画面に表示。破損したDBを黙って作り直さない。
- 設定・結果の保存場所をアプリの設置場所から分離。既存のPDF・出力・モデルは移動しない。

保存場所はWindowsで `%LOCALAPPDATA%\PDF2Markdown`。DB内には変換本文とエラーが含まれます。元PDFと入力URLは保存しません。既定の出力先は同フォルダー内 `output` ですが、サイドバーから任意のフォルダーへ変更できます。ローカル履歴は暗号化・クラウド同期しません。

履歴は自動削除しません。最新20件を一覧表示します。「結果をクリア」は画面の結果だけを消すため、履歴も消したい場合は「選択した履歴を削除」を使用してください。履歴削除は別途書き出したファイルを消しません。画面に表示する20件より古い履歴は、新しい履歴を削除すると順に表示されます。

## 検証

SQLiteのコミット・ロールバックと接続の明示クローズはContext7の `/python/cpython` で公式仕様と照合しました。[Python sqlite3の仕様](https://github.com/python/cpython/blob/main/Doc/library/sqlite3.rst)

自動テストで、別のAppTestセッションへの設定引き継ぎ、中断結果の復元、履歴削除による出力ファイル非改変、トランザクション失敗時の旧結果維持、DB・結果レコードの破損、保存不能時のエラー表示、設定値の検証を確認します。テスト専用の一時フォルダーを使用し、利用者の設定DBは書き換えません。

最終結果は通常テスト34件・敵対的検証19件の計53件成功。生ログはローカルの `audits/evidence/20260916T011238Z-4c6bf361/` と `audits/evidence/20260916T011317Z-35c4e40e/` にあります。両方とも終了コード0を確認しました。変更前のコードはGitコミット `b998472` で復元できます。今回作成した利用者のDBを古いコードへ戻すために削除する必要はありません。

今回確認していないもの：実際の電源断、OSのディスク容量枯渇、実モデルのOCR精度、プロセス強制終了時の子孫プロセス回収。例外注入や別のAppTestセッションでの確認を、それらの実機検証と同一視しません。

## 今回の変更を試す手順

1. 起動中の旧版に未保存結果があれば先に保存し、アプリを終了して `start.ps1` で起動し直す。
2. 保存先とOCR設定を変更し、アプリを終了・再起動して設定が残ることを確認。
3. 小さなテキストPDFを数件、まず「OCRなし」で変換し、MarkdownとZIPを保存。
4. アプリを再起動し、「保存された変換履歴・復元」で結果を復元。保存内容を原文と比較。
5. 履歴を1件削除し、別途保存したMarkdown・ZIPが残っていることを確認。

変換結果の復元は、途中処理の再開ではありません。実行中のPDFを中止するUIはまだありません。環境インストール中にアプリを終了するテストは、プロセス管理の実装後に行います。
