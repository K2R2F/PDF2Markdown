## 維持できている動作

- 同名への24件の同時保存で、上書きなし・全内容一致。
- 書き込み途中の例外で部分ファイルを除去。
- 空ダウンロードで既存ファイルを維持。
- 通信タイムアウトで接続を閉じる。
- 設定ワーカーの起動失敗で排他を解放し、非ゼロ終了は失敗として保持。
- 子プロセス停止を確認できない場合、failureとblockedを記録して次の設定を拒否。
- Doclingが部分成功とTIMEOUTを返した場合、結果・manifestをsuccessに変更しない。
- 既存の公開IP制限、ZIP容量制限、個別PDFの失敗分離、保存操作、インストーラーSHA-256不一致拒否を回帰テストで確認。

## Context7での照合

Context7には公開ライブラリの仕様だけを問い合わせ、プロジェクトのソースや文書を送信していません。各ライブラリIDをresolveしてからqueryしました。資料は最新版のため、今回重要だったPythonとDoclingの動作はインストール済みのソースでも照合しました。

| ライブラリID | 照合内容 | 判断 |
| --- | --- | --- |
| `/python/cpython` | HTTPResponseのサイズ指定readと途中EOF | サイズ指定readはContent-Length不足でも例外を必ずしも送出しない。Python 3.12の実装と実レスポンス解析でも確認し、独自の受信長検証を追加 |
| `/streamlit/docs` | cache_resourceのセッション間共有・スレッド安全性 | 変換器の共通ロックを維持。グローバルに共有される環境ジョブの異常時排他を重点検証 |
| `/docling-project/docling` | document_timeoutとpartial_success | タイムアウトによる部分成功は全体成功と区別する。Docling 2.126.0のbase/standard PDF pipelineにTIMEOUTとPARTIAL_SUCCESSの処理を確認 |

参照: [CPython HTTP実装](https://github.com/python/cpython/blob/main/Lib/http/client.py)、[Streamlitキャッシュ](https://github.com/streamlit/docs/blob/main/content/develop/concepts/architecture/caching.md)、[Docling PDFパイプライン](https://github.com/docling-project/docling/blob/main/docling/pipeline/standard_pdf_pipeline.py)。Context7のDocling結果にはリポジトリ内パスの表記差があったため、実際の照合はローカルのインストール済みファイルで補いました。
