# PDF→Markdown 試用版 — 2026-10-29

DOCXは対象から切り分け、PDFに集中します。Windowsでソースから起動して試用する段階です。EXE・インストーラーの完成や、任意の原稿に対するOCR精度保証を意味しません。

## 今回の実装

- URL取得・入力検証・Docling/OCRを専用ワーカーへ分離し、画面からキャンセル可能にした。
- バッチ全体の時間上限を1〜120分、標準30分で指定。モデル準備・DNS待ち・読み込み中も親プロセスが時間を監視する。期限後の停止確認時間は別に必要。
- Windows Job Objectで子・孫プロセスを管理。親が終了したときもワーカーを終了させる。
- 管理下に置いてからワーカーへ開始信号を送る。管理の設定に失敗した場合は処理を始めない。
- 同じユーザーデータ領域を使用する別アプリプロセスとの変換・環境設定の重複実行をファイルロックで拒否する。画面を複数開くこと自体は禁止しない。
- キャンセル・時間超過を履歴へ明示し、完了済みPDFの結果を保持する。停止確認不能の場合は排他を保持して追加処理を防ぐ。
- 親アプリの異常終了で残った一時入力は、次の変換開始時に排他を取って回収する。既存の保存済みMarkdownや元ファイルは削除しない。
- 環境設定ワーカーにも同じプロセスツリー管理を適用する。環境インストールの中断からの再開機能は含まない。

バッチごとに変換器を作るため、前の同期方式より起動時間がかかる場合があります。ディスク上のモデルキャッシュは再利用します。画面は進捗の段階と停止操作を表示し、結果本文は終了後に表示します。ブラウザーを閉じてもサーバーが動いていれば処理を続け、結果は履歴に保存されます。

## 試用手順

1. `start.ps1` を実行し、`http://127.0.0.1:8501` を開く。
2. まず小さな文字入りPDFを「OCRなし」で変換し、個別MD・全件ZIPを保存する。
3. 日本語のスキャンPDFでEasyOCR・日本語＋英語を試し、本文・数字・固有名詞を原文と比較する。
4. 複数PDFを追加し、処理中のキャンセルを試す。履歴がキャンセル表示になり、完了済み結果を復元できることを確認する。
5. 通常の資料で表・箇条書き・画像を確認する。誤りは原稿の種類、設定、期待結果、実際の結果を記録する。

不具合報告には原稿全体を必須とせず、可能なら機密情報を除いた再現用PDFを使ってください。複雑な表・縦書き・低解像度・写真・手書きは今回の合成原稿で品質評価していません。RapidOCRの実推論とTesseractの実インストーラー・UACは未検証です。

## 設計・変更点

`execution/pipeline.py` は画面に依存しない変換手順、`worker.py` は処理入口、`controller.py` はキャンセル・期限・状態管理、`process.py` / `windows_job.py` はOSプロセスツリー、`lease.py` は別プロセス間排他です。SQLiteの既存履歴は保持し、新しい状態としてcancelled/timed_out/interruptedを追加します。

Windows Job Objectの終了・子孫管理は [Microsoft公式仕様](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) と照合しました。画面の定期ポーリングはContext7で [Streamlit fragments](https://github.com/streamlit/docs/blob/main/content/develop/concepts/architecture/fragments.md) を確認し、インストール済み1.63.0でAppTestを実行しました。

変更前はGitコミット `4a71cfd` で復元できます。既存履歴を保持したまま旧版へ戻す場合、新状態の表示対応が旧版にはないため新DBを旧コードで使わず、データ配置を分けてください。
